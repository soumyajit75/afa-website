# Amuzi Centre of Excellence — Website

A premium, responsive website communicating: **AFA methodology. International football pathway.
Indian player development.** The Amuzi Centre of Excellence is the flagship destination; only
two brand marks are used site-wide (Amuzi Centre of Excellence + AFA) — the earlier "Amuzi
Sports" brand has been fully removed from logos and copy.

Built as a static HTML/CSS/JS site (no Node.js / build tooling required to run it), assembled from reusable templates and CMS-ready JSON content via a small Python build script. Deployable to any static host.

## Quick start

```bash
# 1. Rebuild HTML from templates + content (only needed after editing source/ or content/)
python3 build.py

# 2. Preview locally
python3 -m http.server 4173
# then open http://localhost:4173/index.html
```

## How the build works

1. `content/*.json` holds the structured data for anything that repeats or will eventually
   come from a CMS (philosophy pillars, pathway stages, FAQs, news, etc).
2. `source/templates/pages/*.html` holds hand-authored page copy, with `{{PLACEHOLDER}}`
   slots where JSON-driven content should be injected (e.g. `{{PATHWAY_STAGES}}`).
3. `build.py` renders each JSON collection into markup, drops it into the matching page
   template, wraps it with the shared header/footer + base document shell, and writes the
   final static HTML file to the project root.
4. Editing copy: change the relevant file in `source/templates/pages/`, then re-run
   `python3 build.py`. Editing repeating content (FAQ, pathway, programmes, etc.): edit the
   JSON file in `content/`, then re-run the build.

This keeps content separate from markup — the JSON files are a realistic first step toward
a future headless CMS migration without needing a framework today.

## Design system

All brand tokens live in `assets/css/tokens.css`:

- **Colour** — one consistent Indian Navy Blue background (`--bg` `#0A2049`) runs through
  every section on every page, plus Metallic Gold `#D4AF37` as the premium accent. This is
  deliberately *not* Argentina sky blue, and section backgrounds never switch to black/white —
  depth comes from translucent glass panels (`--surface`, `.card`) and gold borders instead of
  a different hue. Two brand gradients (`--gradient-sky` — now an Indian-blue gradient, kept
  under its original name so components didn't need renaming — and `--gradient-gold`).
  Indian Flag Saffron (`--saffron` `#FF671F`) is a third, deliberately restrained accent —
  used only for the `.eyebrow--saffron` variant, whose accent bar blends blue into saffron to
  read as "Argentina × India" at a glance. It is never used as a background block.
- **Type** — headings use `--font-heading` (currently mapped to **Archivo**, a placeholder
  for the licensed **TT Interphases** files the brief specifies — swap the font-family and
  add `@font-face` rules once licensed files are available). Sub-headings/nav/buttons use
  **Poppins**. Body copy uses **DM Sans**.
- **Spacing / radii / shadows** — a restrained scale (`--sp-1`…`--sp-10`, `--radius-sm/md/lg`,
  `--shadow-sm/md/lg`), used consistently across `components.css` and `sections.css`.

Reusable components (`assets/css/components.css`): `.btn` (primary / sky / gold / ghost /
outline variants), `.card` (+ programme / pillar / news / stat variants), header/footer,
accordion, form fields, audience switch.

## Logos

Only **two** brand marks appear anywhere on the site — the Amuzi Sports wordmark has been
removed from every page (header, footer, homepage, cards, CTAs). See `assets/img/logos/`:

- `acfe-onblue.png` / `acfe-onlight.png` — the Amuzi Centre of Excellence lockup, cropped and
  matted to transparency from the supplied `ACFE_Black/White.PNG`. This is now the **primary**
  mark — it's the header's home-link logo, the footer's main logo, and stands in for the
  "Amuzi Centre of Excellence" heading text in the homepage flagship-destination section.
- `afa-crest.png` — the official AFA crest, cropped from `AFA logo.jpeg` and matted to true
  transparency (re-exported as PNG; the original JPEG has no alpha channel, so it needed the
  same colour-distance matting treatment as the PNG marks). Sized smaller than the ACFE mark in
  the header/footer so it reads as the methodology partner, not a co-equal or dominant brand.
- `amuzi-sports-onblue.png` / `amuzi-sports-onlight.png` — the old Amuzi Sports wordmark.
  **No longer referenced anywhere** in `source/templates/`; left in the folder only in case a
  future use case needs it, safe to delete.
- The original hand-drawn placeholder marks (`mark-amuzi.svg`, `mark-acfe.svg`,
  `mark-afa-placeholder.svg`) are likewise unused; safe to delete.
- Regenerate any processed logo from a fresh source file with the same crop + colour-distance
  matting approach (Pillow) used to produce the current files.

## Argentina/AFA photography

Real photography has been sourced from the client-supplied `AFA Academy Deck 2024.pdf` and
`Argentina National Team - Deck 2024.pdf` (in `Argentina Decks/`), extracted with PyMuPDF and
reviewed image-by-image. Only images with **no third-party academy branding** (several images in
the academy deck show unrelated partner sites — e.g. a Madrid facility co-branded with
"Vallecas CF" — and were excluded, since using them would misleadingly imply Amuzi is affiliated
with those specific outside organisations) were selected. The final set — Argentina National
Team player photography, training shots, and an AFA honours graphic — lives in
`assets/img/photos/`, with two studio/white-background source images matted to transparent PNG
using the same Pillow colour-distance technique as the logo processing (see `assets/img/logos/`
notes above; tune `thresh_low`/`thresh_high` conservatively — too wide a threshold band will eat
bright skin highlights, not just true background).

Every photo is captioned/alt-texted to honestly attribute it to the **Argentina National Team /
AFA methodology partnership** — never implying it depicts Amuzi's own India-based facilities,
coaches or players. Facility-specific claims (the Centre of Excellence "Training Facility" slot)
still use the `field-facility.svg` illustration, since no genuine photo of Amuzi's own build
exists yet — see "Known placeholders" below.

## Scaling this site later

The structure is intentionally CMS-ready and framework-agnostic:

- Swap `content/*.json` for calls to a headless CMS (Sanity, Contentful, etc.) without
  touching the page markup structure.
- Each page template is self-contained — adding a new page (e.g. individual player profiles,
  a locations directory, an events calendar) means adding one file to
  `source/templates/pages/`, registering it in the `PAGES` list in `build.py`, and adding a
  nav link in `source/templates/partials/header.html`.
- If/when the project outgrows static generation (parent dashboards, live match data,
  authenticated registration), the same design system (`assets/css/*`) and component
  patterns can carry directly into a framework like Next.js — nothing here is
  static-site-specific beyond `build.py` itself.
